# Chess coach: Caro-Kann (Black)

A single-page web app. **Learn** is a reflex game with four paths, the Caro-Kann (you're Black, vs 1.e4), Against d4 (you're Black: the Slav and vs the London), the Queen's Gambit (you're White) and Principles (one basic rule per run, you're White): the other side throws a move, you counter before a timer runs out; **Play** is Stockfish 19 in the browser, and after each move the coach explains, in plain words, what was wrong and shows it on the board. Live on GitHub Pages: https://elijahgerak.github.io/chess-coach/ (served from the `gh-pages` branch; `main` holds the source).

## What the owner wants (read before changing anything)

- **Minimal, no bloat.** Don't add features, settings or screens unless asked. When in doubt, cut. Three tabs only: Learn, Play, Review. Learn has four paths (Caro-Kann, Against d4, Queen's Gambit, Principles; a 2×2 switch); Play is Caro-Kann only for now (its bot can now open 1.d4 too, since those lines live in `REPERTOIRE.caro`).
- **"If it's not simple, it's wrong."** Learning should feel effortless and *not like a lesson or like memorizing*. The owner rejected lessons (watch → copy → solo), level paths and story missions as "still a normal method". Learn is an arcade reflex game; keep it that way. It should barely feel like chess (no coordinates on the Learn board, no square names in its captions).
- **Assume the user knows nothing.** Every screen has one obvious next action. No thinking required.
- **Make them think, don't hand them moves.** Following arrows taught nothing. The user always tries first: the card gives the *idea*, a Hint button adds more one step at a time (idea → which piece → the move), and threats are asked ("Which piece is under attack?"), not told. End of game shows "You found X of Y moves yourself."
- **Plain words only.** Treat the user as a complete beginner. No chess jargon ("pawn chain", "develop", "open file", "minority attack", "IQP", "tempo") and no move notation in coaching text ("Nge7"). Use pieces and squares: "Attack the pawn on d4. It's holding up the pawn on e5." / "Better: knight g8 → e7." (`moveWords`, `describeMove`, `describeTheirs`).
- **Feedback = short.** One sentence of reason, `Better: <move>`, one `Rule:` (a true, basic principle), and the moves played out on the board. No paragraphs.
- **No Claude/AI inside the app.** All coaching comes from Stockfish + the rules in `core.js`. Don't add LLM calls.
- **Look:** modern and clean: Geist font, rounded cards, black pill buttons, floating tab bar, subtle film grain, light/dark themes. Motion follows Emil Kowalski: fast ease-out (`--ease-out`), 150–300 ms, nothing bouncy, respect reduced motion. Also influenced by "impeccable" and "taste" design guidance: no generic AI-template looks.
- **Logo:** a 3D render of a white pawn pressing a barbell with green plates, studio-lit on a black background (`brand/render.py`). Modern and very clean. It's the home-screen icon, header logo and favicon.
- **Rules must be accurate.** Never show a principle that isn't true for the position. Run `npm run test:book` after changing the repertoire.
- Learning design is research-based: generate the answer yourself before seeing it, minimum help needed (hint ladder), guidance that fades as skill grows, spaced practice, principles tied to concrete squares.

## Commands

```bash
npm install && npm test   # quick checks (needs Node; tests run the vendored engine in Node)
npm run test:book         # slow: engine-checks every taught move and concept answer
npm run serve             # http://localhost:8765 (must be served over http; file:// can't start the engine worker)
python3 tests/smoke.py    # headless UI check, screenshots in tests/screens/
npm run deploy            # publish to GitHub Pages
```

## How the main flows work

- **Learn (home, `#learn`): reflex duel in runs.** A Caro-Kann / Against d4 / Queen's Gambit / Principles switch sits at the top (`S.duel.path` = `caro` / `slav` / `qg` / `rules`; `PATHS` in ui.js gives each path its side and runs; the board is flipped for Black). Against d4: the 1.d4 lines in `REPERTOIRE.caro` (Slav main, knight first, quiet e3, White swaps on d5, the London with ...c5 and ...Qb6), 28 answers in 4 runs (`D4_RUNS`: White starts with d4, White attacks with c4, Quiet moves and swaps, The London) plus Everything; `DECKS.caro` / `DECKS.slav` split the Caro deck by first move. Principles: 6 runs of 5 positions (Take free pieces, Bring your pieces out, Castle early, Take the middle, Move attacked pieces, Look for checks first) plus Everything; the run's rule shows above the run card and its name is the chip during play. Queen's Gambit: 55 answers in 9 runs (your first moves, Black holds with e6 ×2, you swap on d5, Black takes the pawn, Black holds with c6, Black builds a wall, Black gives up a pawn, Black hits back with c5) plus Everything. Caro-Kann: the 53 answers are split into 8 runs (`RUNS` in `data.js`: White's first moves, White protects, White protects part 2, White pushes, White swaps, White attacks with c4, Surprise pushes, Surprise starts) plus "Everything" (15 random positions from the whole deck). **Clear a run 3 times** (finish with at least one heart) to open the next; earlier runs always stay open for more reps. Out of hearts doesn't count. Home shows one run at a time: the current one (first open run with fewer than 3 clears) with its 3 dots and a Play button, plus "‹ Earlier run" / "Next run ›" to step through open runs (`S.duel.progress[id] = {clears, best}`). **Every run = learn the new, then review everything:** a run plays its own (new) positions in line order once, then a shuffled review of every position you've seen from the earlier runs in that path *plus* the new ones (the owner found earlier runs didn't stick without this; don't cut it back to a sample). A miss puts that position back 3 rounds later (the run gets one round longer). Each answer also keeps a strength (`box`, `due`: right → 1, 2, 4, 8, 16, 30 days; wrong → reset), and Everything plays the 15 weakest. The run card says "5 new, then a review of all 16 you know". **Pace (the owner tuned this; don't change it without asking):** each replayed move takes 60 ms whatever the line length (the owner's favourite: very fast but still easy to follow; squeezing every replay into a fixed time made short lines feel slow), the next round starts 0.8 s after a right answer, and nothing waits on a button. Faster than this felt rushed; a timer that starts long felt slow. Each round the board fast-forwards to the position (`zipTo`), then White "throws" its move (whoosh + colored family chip). **First time ever seeing a position:** no timer, the ghost shows the answer + one-line reason; copy it. **After that:** a 3-second timer, every time (the owner wants it fast, always), any repertoire move counts. Right = pop + chime ("Lightning!" under 1 s) + points (50–100 by speed, ×2 at combo 5, ×3 at 10). Wrong or too slow = lose a heart, ghost + reason, copy it to continue. Per position: `S.duel.cards[key] = {seen, ok}`. Leaving the tab or hiding the page stops/pauses the run. During a run the tab bar hides and the timer is a thick bar along the bottom of the screen (green → yellow → red). Double-tap zoom is off (`touch-action: manipulation` + viewport `user-scalable=no`); keep it that way. Sounds are WebAudio tones, toggled in Settings.

- **Your-move card (`nextCardHTML`):** context line in plain words ("White moved their knight to g3." + the idea of their move), then "Your move." At help level 1 (`S.guide.stage`) the **Idea** line shows automatically (top repertoire move's comment, else `whyFor` → `principleFor`/`shortIdea`/plan step); the Hint pill then adds **Piece** (blue box) and **Move** (words + green arrow). Level 2 shows nothing until Hint. A move counts as "found yourself" if it's book/best/excellent with at most the idea shown; 25 in a row moves you to level 2, a game with 3+ mistakes moves you back. After an opponent move that leaves one of your pieces hanging, a **threat question** ("Which piece?", 3 choices) comes first; the answer rings the piece. Last-move line: "✓ You found it." (plus the rule if you hadn't seen the idea), or a short card for good/inaccurate moves.
- **Play:** on your turn `coachEngine` analyzes the position (MultiPV 3). When you move, it analyzes the new position; `explainMove` compares win% before/after (thresholds: inaccuracy ≥6, mistake ≥11, blunder ≥20 points, softened when already winning/lost). Book moves skip analysis. Mistakes/blunders pause the game, auto-replay `r.show` on the board, and offer Try again / Keep playing. The bot plays repertoire replies first (weighted), then Stockfish at the chosen level (`LEVELS`: under 1320 Elo uses depth-limited MultiPV with softmax picking; above uses `UCI_LimitStrength`). Strength moves up on a win, down on a loss.
- **Opponent mistakes:** after the bot moves, the new eval is compared with the eval after your last move; a ≥10-point swing flags it ("Black's 12...Nc3 was a blunder. Find the move that punishes it.").
- **Plans:** `detectStructure` picks a `PLANS` entry from the pawns. At help level 3 the card shows the next unfinished step and the attacker/defender count on the `focus` square, and the board rings that square. "See the plan" opens the full plan + goal checklist. No structure → opening/middlegame/endgame `GOALS`, with the relevant pieces ringed. (`PLANS.quiz` is unused for now.)
- **Threat questions:** after the bot moves, if one of your pieces is attacked and unguarded (or attacked by something cheaper), you're asked which piece it is before you move. They fade: off after 3 games in a row with no hung piece/fork/allowed mate, back on after 2 such slips in one game (`S.threat`).
- **End of opening:** the first time a game leaves the repertoire, the context line says "The opening is over. Think about your plan."
- **Review:** paste PGN (chess.com comments/clocks are stripped), pick your side once (remembered as `S.username`), every position analyzed at depth 12, up to 5 key moments where you find the better move first, then the game move + refutation replays.
- **Storage:** `localStorage` key `ckqg-coach-v1`. Inside a Claude artifact it also syncs through the artifact `db` (`window.claude.use("db")`); on Pages that's simply absent.

## Conventions

- chess.js **0.10.3** from cdnjs (old snake_case API: `in_check()`, `game_over()`, `load_pgn()`, `moves({verbose:true})`).
- Copy is plain, short, sentence case, from the player's side ("Your bishop on d6 can be taken for free."). No jargon, no notation. Repertoire comments in `data.js` follow the same rule (they become the Idea line).
- Keep `core.js` free of DOM so it stays testable in Node (`tests/lib.js` loads it).
- Adding content: a repertoire line is PGN text with `{comment}` after the move it explains and a `weight` (how often the bot picks it). Every Black move in the repertoire becomes a duel card automatically, and its `{comment}` is the reason shown with the ghost, so every Black move needs a comment. Then add the new position to a run in `RUNS` (keep runs at 4–8 answers; the data test checks every answer is in exactly one). Then run `npm test && npm run test:book`.
- Motion uses the Web Animations API with per-keyframe easing (whole-iteration easing on a looping ghost makes it race to the end). Everything checks `prefers-reduced-motion`.
- Commits go to `main`; run `npm run deploy` to publish.
